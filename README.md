# AmazonLinks for Geeklog

AmazonLinks adds contextual Amazon affiliate links to Geeklog stories by matching configurable keywords or phrases.

## Version 1.1.0

This release replaces the executable PHP configuration used by 1.0 with:

- Geeklog Configuration API for general settings.
- Private JSON storage for contextual rules.
- An administration page protected by `amazonlinks.admin`.
- Atomic JSON writes and CSRF protection.
- HTTP/HTTPS URL validation.
- Correct affiliate query handling.
- `rel="nofollow sponsored noopener"` for affiliate links.
- Configurable Amazon marketplace.
- Whole-word, phrase and substring matching.
- Rule priorities and optional Geeklog topic restrictions.
- `[amazonlinks:...]` autotag support.
- Automatic story display mode with no theme modification required.
- Optional `{amazonlinks}` template-variable mode for precise placement.
- Separate frontend CSS.
- English and French language files.
- No Composer, external API, telemetry or plugin-specific database tables.

## Requirements

- Geeklog 2.1.1 or later.
- PHP 5.6 or later.

The code intentionally avoids PHP syntax introduced after PHP 5.6.

## Installation

1. Upload/install the plugin using Geeklog's plugin installer.
2. Open **Command & Control → Amazon Links**.
3. Open the general configuration and set your Amazon marketplace and affiliate tag.
4. Configure contextual rules.
5. Choose the display mode:

   - **Automatic after story** (default): no theme modification required.
   - **Template variable `{amazonlinks}`**: add `{amazonlinks}` where you want the contextual block, typically in:
     - `article/storytext.thtml`
     - `article/featuredstorytext.thtml`
   - **Disabled**: contextual story blocks are not rendered.

## Private data

Rules are stored in a sibling directory derived from Geeklog `path_data`.

If `path_data` is:

    /home/account/data/

AmazonLinks stores its JSON rules in:

    /home/account/data-amazonlinks/rules.json

This avoids executing writable PHP configuration files and keeps plugin data separate from Geeklog's generic data directory.

## Upgrading from 1.0

Version 1.0 used:

    {path_data}/amazonlinks_config.php

Version 1.1 deliberately does **not** include or execute that writable PHP file.

If it is still present, the administration page displays a warning. Recreate the required rules in the new administrator interface, then archive or delete the legacy PHP file manually after verifying the migration.

The file is not removed automatically because it may contain user-maintained data.

## Display modes

### Automatic after story

This is the default. AmazonLinks uses Geeklog's native template-variable hook and appends the generated block to the visible article text on the full article page. No theme modification is required.

Automatic mode is deliberately limited to the full article display (`story_display_type = n`), so Amazon links are not repeated below every article summary on topic and index pages.

### Template variable

Select this mode when the theme should control the exact position. Add:

    {amazonlinks}

to the desired story template. Automatic insertion is disabled in this mode, so the block is never rendered twice by AmazonLinks.

### Disabled

The contextual story block is disabled. Autotags can still be used.

## When a contextual block appears

A block is rendered only when at least one enabled rule matches the article title, introduction or body content. The shipped example rules match `windows` and `linux`. For testing, create a rule whose keyword or phrase is definitely present in one of these article fields.

If article/template caching is enabled, clear Geeklog's cache after changing the plugin code or rules during testing.

## Rule fields

- **Keyword / phrase**: text searched in the article.
- **Label**: link text shown to visitors.
- **Type**:
  - `search`: Amazon search query generated by the plugin.
  - `url`: complete HTTP/HTTPS product or search URL.
- **Target**: Amazon query or complete URL.
- **Match**:
  - `word`: whole-word Unicode-aware match.
  - `phrase`: case-insensitive phrase match.
  - `substring`: simple partial match.
- **Topic ID**: optional Geeklog topic ID; blank or `all` applies everywhere.
- **Priority**: higher values are evaluated first.
- **Enabled**: turns the rule on or off.

## Autotags

Search:

    [amazonlinks:libreoffice]

Search with a custom label:

    [amazonlinks:libreoffice|Voir les livres sur LibreOffice]

Product ASIN:

    [amazonlinks:asin:B0XXXXXXXX]

Product ASIN with a custom label:

    [amazonlinks:asin:B0XXXXXXXX|Voir ce produit sur Amazon]

The `|` separator is parsed by AmazonLinks itself, so multi-word search terms and labels are unambiguous. If Geeklog also supplies a second autotag parameter, AmazonLinks continues to accept it for compatibility, but an inline label after `|` takes precedence.

The autotag name is deliberately `amazonlinks` rather than `amazon` to avoid collisions with existing or legacy manual Amazon autotags on Geeklog sites.

## Affiliate links

The plugin adds the configured Amazon affiliate tag without blindly appending a second `tag` parameter. Existing query parameters and URL fragments are preserved.

Existing affiliate tags are removed case-insensitively before the configured tag is added. This prevents imported direct URLs from crediting a different Associates account.

Contextual and autotag links use:

    rel="nofollow sponsored noopener"

## Uninstallation and data retention

Geeklog removes the plugin group and permissions through the standard autouninstall mechanism.

The private `data-amazonlinks` directory is intentionally **not deleted automatically**, because it can contain user-created rules. Remove it manually only when you are certain the data is no longer needed.

## Security

AmazonLinks 1.1:

- does not execute mutable configuration files;
- accepts only `http` and `https` direct rule URLs;
- escapes generated HTML attributes and labels;
- uses Geeklog permissions for administration;
- uses Geeklog CSRF tokens when rules are saved;
- writes JSON through a temporary file followed by an atomic rename;
- has no outbound reporting or telemetry.

## Configuration bootstrap safety

AmazonLinks keeps initial configuration creation separate from upgrade migration. Runtime configuration loading falls back to safe defaults if the AmazonLinks configuration group is not yet available. This reduces interference with Geeklog's own configuration page while preserving compatibility with older installations.

## Built-in administrator documentation

The AmazonLinks administration page includes a collapsed documentation section at the bottom. It covers quick setup, display modes, contextual rules, affiliate-tag replacement, autotags and data storage.

## Button color

The contextual Amazon buttons can follow the active theme or use one of the built-in color presets:

- Theme color
- Blue
- Green
- Orange
- Red
- Dark
- Gray

The default is **Theme color**, which avoids forcing a visual style on the active Geeklog theme.
